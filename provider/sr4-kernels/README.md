# SR4 skipped-frame kernels: source and build

Two compute kernels that the Vela FSR 4 provider (`amd_fidelityfx_upscaler_vk.dll`, built from `../`) runs on the frames it skips in the
lossy N > 1 modes. They are embedded in the DLL as SPIR-V arrays from `../overlay/gen/fsr4sr4-spv.hpp`.

| file | what |
|---|---|
| `src/sr_r4.comp` | `sr_r4`: reprojects the previous output and applies the rest / uncovered / edge rules. Generated by `tools/gen_r4.py` from `src/sr_r.comp` (`gen_r4.py` regenerates it byte for byte) |
| `src/sr_w.comp` | `sr_w`: the FSR 4.1.2 Lite K2 pass on the warped feature plane, with the skipped-frame blend |
| `tools/` | `gen_r4.py`, the SPIR-V steps for `sr_w` (`sudot.py`, `zconst.py`, `zforce.py`, `wlit.py`, `cres.py`, `kfold.py`), `weights.bin` (the Lite K2 weights, 27 392 bytes, the same words as in `../overlay/ov2/fsr412lite-blobs.hpp`), `gen_hpp.py` (SPIR-V to C++ header), `compile.sh` (the build inside the container) |
| `LICENSE` | GNU GPL version 2 (text of the upstream project's `LICENSE`) |

## License and upstream
- The kernels are **GPL-2.0-or-later**: their rule code is derived from [fsr4-shader-performance-overrides](https://github.com/zgauthier2000/fsr4-shader-performance-overrides)
  (GPL-2.0-or-later, `LICENSE` md5 `f6b273a0a9f3f45338fea41cb0dfdb27`, checked at commit `cf7432703553357dcda5fc30e0e27546fafe1164`), the FSR 4.1.2 lossy frame-skip shaders.
  GPL-2.0-or-later code may be combined under GPLv3, so the provider DLL as a whole is GPL-3.0 (see `../README.md`).
- The `sr_w` kernel is built on AMD's FSR 4.1.2 Lite K2 pass and its weights: AMD's MIT notice is in `../../plugin/assets/licenses/fsr4vk/AMD-FidelityFX-SDK-MIT.md`.
- The sources here are our own derived work, not a copy of a public upstream file, so they are published in this folder (a link to the upstream project is not enough for them).
  The upstream project is linked above for the rules they derive from.

## Build
From this folder, with Docker and network access: `sh build.sh` (about 1 minute). Inside `ubuntu:24.04` it installs `glslang-tools 15.1.0-2~ubuntu0.24.04.2` and
`spirv-tools 2025.1~rc1-1~ubuntu0.24.04.2`, then
1. regenerates `sr_r4.comp` from `sr_r.comp` with `gen_r4.py` and checks it is identical to `src/sr_r4.comp`;
2. builds `out/sr_r4.spv` (`glslangValidator -V --target-env vulkan1.3`, `spirv-opt -O`);
3. builds `out/sr_w.spv` (glslang, then the weight-folding steps in `tools/compile.sh`, then `spirv-opt` constant folding);
4. writes `out/fsr4sr4-spv.hpp` and compares it with `../overlay/gen/fsr4sr4-spv.hpp`.

Expected: `sr_r4.spv` md5 `e51e988ab197c4785cf34ec9b5214931` (28 900 bytes), `sr_w.spv` md5 `b59e9df1aca0ee9c234bced13ef03170` (56 188 bytes), and the last line
`OK: fsr4sr4-spv.hpp identical to overlay/gen/fsr4sr4-spv.hpp`. The provider build in `../` embeds that header; both arrays appear byte for byte in the shipped DLL.
